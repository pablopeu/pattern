## 1. Objetivo del producto

Desarrollar una aplicación web 2D que permita:

- Crear geometría vectorial libremente.
- Generar patrones paramétricos a partir de geometrías propias o de generadores incorporados.
- Aplicar transformaciones, repeticiones, simetrías y teselaciones matemáticas complejas.
- Visualizar inmediatamente el resultado mientras se dibuja o modifican parámetros.
- Conservar editable la geometría original y todas las propiedades que generan el patrón.
- Aplicar cualquier patrón a un perímetro irregular definido por el usuario.
- Exportar resultados vectoriales exactos y archivos rasterizados de alta calidad.
- Guardar y recuperar proyectos completos.

### Principio rector

> Cualquier geometría vectorial 2D editable debe poder convertirse en un patrón mediante transformaciones matemáticas. El patrón resultante debe poder reutilizarse, parametrizarse y aplicarse de manera no destructiva a cualquier región plana definida por un perímetro cerrado.

El programa no debe estar orientado a una industria, oficio o proceso de fabricación específico.

No debe imponer limitaciones artificiales sobre las formas del perímetro de aplicación.

### Fuera de alcance

- Modelado 3D.
- Renderizado 3D.
- Simulación de materiales.
- Texturas volumétricas.
- CAD mecánico generalista.
- Inteligencia artificial generativa.
- Servicios en la nube.
- Colaboración multiusuario.
- Gestión comercial.
- Cuentas, suscripciones y pagos.
- Backend obligatorio.
- Aplicaciones móviles nativas.

## 2. Plataforma y distribución

### 2.1 Arquitectura de despliegue

La solución MUST ser una aplicación web estática que pueda ejecutarse íntegramente en el navegador.

El despliegue prioritario será:

**Opción A — Hosting compartido convencional**

- Archivos HTML, CSS, JavaScript y assets estáticos.
- Instalación mediante FTP o copia de archivos.
- Sin Node.js en el servidor de producción.
- Sin PHP, MySQL ni base de datos.
- Sin API remota.
- Compatible con instalación en un subdirectorio de un dominio.
- Ruta base configurable al compilar.

**Opción B — Debian headless, red local**

La misma compilación MUST poder servirse desde una máquina Debian sin escritorio gráfico, mediante un servidor HTTP estático sencillo.

El procesamiento geométrico se realizará en el navegador del equipo cliente.

El servidor Debian no necesitará GPU, interfaz gráfica ni servicios de renderizado.

### 2.2 Operación sin conexión

La aplicación MUST funcionar sin acceso a Internet cuando sus archivos estáticos se encuentren disponibles localmente.

No debe depender de CDN, fuentes externas ni servicios de terceros en tiempo de ejecución.

Un service worker/PWA puede mejorar el uso offline bajo HTTPS o localhost, pero **no debe ser necesario para funcionar mediante HTTP en una LAN**.

### 2.3 Stack preferido

- React + TypeScript + Vite.
- Paper.js para edición vectorial, geometría Bézier y operaciones sobre paths.
- SVG nativo para intercambio y exportación.
- Canvas 2D y/o SVG optimizado para visualización.
- Web Workers para procesamiento pesado cuando corresponda.
- IndexedDB para autosave y almacenamiento local.
- Vitest para pruebas unitarias.
- Playwright para pruebas funcionales.

Codex puede sustituir una biblioteca si demuestra técnicamente que otra resuelve mejor las necesidades. El motor de simetrías y los modelos persistentes deben permanecer independientes del framework visual.

## 4. Motor de geometría vectorial

### 4.1 Objetos editables

MUST soportar:

- Segmentos rectos.
- Polilíneas.
- Paths abiertos y cerrados.
- Curvas Bézier cúbicas.
- Rectángulos.
- Rectángulos redondeados.
- Círculos.
- Elipses.
- Polígonos regulares y libres.
- Paths compuestos.
- Grupos de objetos.
- Objetos procedurales editables mediante parámetros.

### 4.2 Edición

Cada elemento MUST permitir, según su naturaleza:

- Trasladar.
- Rotar.
- Escalar.
- Reflejar.
- Duplicar.
- Modificar nodos.
- Modificar tangentes Bézier.
- Convertir segmentos rectos en curvas y viceversa.
- Abrir y cerrar paths.
- Insertar y eliminar nodos.
- Cambiar propiedades de trazo y relleno.
- Transformar objetos individuales o grupos.

Para shapes paramétricas, conservar sus parámetros originales hasta que el usuario elija explícitamente convertirlas en paths.

### 4.3 Operaciones booleanas

Soportar para regiones cerradas:

- Unión.
- Intersección.
- Diferencia.
- Diferencia inversa.
- Diferencia simétrica.

Admitir paths compuestos y agujeros.

Estas operaciones MUST producir geometría real cuando se solicite un resultado expandido.

### 4.4 Edición no destructiva

El documento mantiene una geometría fuente canónica.

Las transformaciones del patrón no reemplazan ni destruyen esa geometría.

Si un objeto se repite 500 veces, debe seguir existiendo un solo objeto fuente editable y un conjunto de transformaciones.

No almacenar 500 copias independientes como modelo principal.

### 4.5 Edición desde una instancia repetida

El usuario debe poder seleccionar una instancia visible y editar el objeto fuente desde ella.

Para ello, el sistema debe identificar la transformación asociada a esa instancia y utilizar su inversa para interpretar las operaciones de edición.

La modificación debe propagarse inmediatamente a las demás instancias.

Esto debe funcionar también con reflexiones y rotaciones, no solamente con traslaciones.

## 5. Motor de simetrías y teselaciones

Este es uno de los componentes principales del proyecto.

No implementar las simetrías como una colección de efectos gráficos aislados.

Construir un motor geométrico reutilizable, basado en transformaciones y grupos matemáticos.

### 5.1 Transformaciones fundamentales

- Traslación.
- Rotación respecto de un centro.
- Reflexión respecto de una recta arbitraria.
- Reflexión con deslizamiento.
- Composición de transformaciones.
- Transformación inversa.
- Transformaciones afines 2D.

Utilizar matrices homogéneas 3 × 3 o una representación matemáticamente equivalente.

### 5.2 Grupos periódicos del plano

MUST implementar los **17 wallpaper groups**:

- p1
- p2
- pm
- pg
- cm
- pmm
- pmg
- pgg
- cmm
- p4
- p4m
- p4g
- p3
- p3m1
- p31m
- p6
- p6m

Cada grupo debe tener:

- Generadores matemáticos correctos.
- Celda fundamental identificable.
- Base de red apropiada.
- Transformaciones reproducibles.
- Vista previa de la simetría.
- Ejemplo preconfigurado.
- Pruebas de invariancia.

Respetar restricciones geométricas de las redes, como relaciones entre ángulos, longitudes y centros de rotación.

### 5.3 Grupos de friso

Implementar los siete frieze groups, utilizando una nomenclatura documentada y consistente.

Permitir repeticiones infinitas en una dirección y dimensiones configurables en la otra.

### 5.4 Simetrías radiales

Implementar:

- Grupo cíclico Cn.
- Grupo diédrico Dn.
- Rosetas.
- Reflexiones radiales.
- Disposición caleidoscópica.

Cantidad de sectores configurable, inicialmente entre 2 y 64.

El centro puede moverse libremente.

Estas construcciones no deben anunciarse como periódicas si no cumplen esa propiedad.

### 5.5 Distribuciones y teselaciones adicionales

Incorporar:

- Grilla rectangular.
- Grilla desplazada por filas o columnas.
- Red oblicua.
- Red triangular.
- Red hexagonal.
- Distribución circular.
- Distribución elíptica.
- Distribución libre.
- Teselación aperiódica Penrose, como generador de regiones finitas.

La distribución libre permite posicionar motivos manualmente, manteniendo sus referencias editables.

**Diferenciar dos conceptos:**

- Distribución de motivos.
- Simetría matemática del patrón.

No tratarlos como equivalentes.

### 5.6 Reglas matemáticas de continuidad

Una figura visualmente continua no es necesariamente un patrón periódico.

El sistema MUST distinguir:

- `PERIODIC_SEAMLESS`
- `FINITE_NONPERIODIC`
- `UNVERIFIED`

Un patrón periódico debe definirse mediante una red de traslación y un conjunto de transformaciones compatibles.

Las redes no ortogonales deben conservar su geometría verdadera.

No deformar automáticamente una red oblicua para introducirla en una baldosa rectangular.

Cuando una exportación rectangular seamless no sea matemáticamente válida, ofrecer la exportación mediante vectores de red o una región finita expandida, informando la diferencia.

### 5.7 Warps y compatibilidad con simetría

Las deformaciones deben preservar las condiciones necesarias para mantener la periodicidad cuando se solicite un patrón seamless.

Para una red de vectores `a` y `b`, una deformación periódica debe cumplir las condiciones de compatibilidad por traslación.

Las deformaciones arbitrarias pueden romper simetrías adicionales de reflexión o rotación.

Por ello:

- Un warp incompatible no debe presentarse como preservador de un wallpaper group determinado.
- Para simetría estricta, restringir o adaptar las deformaciones permitidas.
- Si el usuario elige una deformación libre incompatible, informar qué propiedad se pierde.
- No introducir falsos cierres o uniones artificiales para ocultar discontinuidades.

## 6. Constructor de patrones paramétricos

### 6.1 Concepto

El editor debe permitir tanto construir un patrón desde geometría propia como partir de familias paramétricas predefinidas.

El constructor no debe limitarse a repetir un SVG.

### 6.2 Familias iniciales

Implementar como módulos independientes:

1. **Basic Grid:** repetición regular y escalonada.
2. **Warp Grid:** variación paramétrica de una retícula.
3. **Radial:** composición de motivos alrededor de un centro.
4. **Rosette:** configuraciones circulares de líneas y formas.
5. **Wave:** patrones basados en funciones ondulatorias.
6. **Guilloché:** curvas combinadas paramétricamente.
7. **Spirograph:** curvas trocoidales.
8. **Lattice:** estructuras basadas en redes.
9. **Tessellation:** distribución geométrica por reglas de teselación.
10. **Freeform Arrangement:** colocación y transformación manual de motivos.
11. **Penrose:** generación aperiódica mediante reglas de subdivisión o una metodología equivalente.

Cada generador debe producir geometría o instrucciones geométricas reutilizables, no simplemente una imagen rasterizada.

### 6.3 Parámetros

Según el generador:

- Tamaño.
- Ancho.
- Alto.
- Relación de aspecto.
- Cantidad de elementos.
- Número de filas.
- Número de columnas.
- Espaciado.
- Desfase.
- Rotación.
- Escala.
- Relación de escala.
- Redondez.
- Amplitud.
- Frecuencia.
- Fase.
- Intensidad de deformación.
- Semilla aleatoria.
- Orden de repetición.
- Número de sectores.
- Origen.
- Densidad.

Todos los parámetros deben poder ajustarse mediante controles visuales y valores exactos.

Un parámetro que no aplica al generador seleccionado no debe mostrarse.

### 6.4 Warp Grid

Tomar como referencia el concepto mostrado en Patturn Studio.

Distinguir explícitamente:

- **Freeform:** distribución o modificación libre de posiciones.
- **Rectangular:** distribución según ejes de una retícula.
- **Circular:** distribución radial alrededor de un origen.

El cambio de modo debe ser interactivo y no destructivo.

Permitir deformaciones ondulatorias, desplazamientos y variaciones de escala mediante funciones parametrizadas.

Cuando se requiera periodicidad, aplicar las restricciones de la sección 5.7.

### 6.5 Semillas determinísticas

Todos los generadores con aleatoriedad MUST aceptar una semilla explícita.

Los mismos parámetros, semilla y versión del algoritmo deben producir la misma geometría.

Guardar la versión del generador en el proyecto.

La opción Randomize debe generar y guardar una nueva semilla; no introducir variaciones invisibles en el resultado.

### 6.6 Composición

Permitir utilizar una geometría propia como motivo de un generador.

Por ejemplo:

1. Dibujar tres formas.
2. Agruparlas.
3. Seleccionar Warp Grid.
4. Cambiar distribución y spacing.
5. Aplicar una simetría.
6. Editar nuevamente cualquiera de las tres formas.

El sistema debe preservar las relaciones entre el motivo fuente y la composición.

## 7. Visualización interactiva seamless

### 7.1 Requisito fundamental

**El patrón MUST actualizarse durante el trazado.**

No esperar al evento de finalizar dibujo.

Si el usuario comienza una línea y desplaza el cursor, sus instancias deben visualizarse en tiempo real.

La misma regla se aplica a:

- Movimiento de nodos.
- Cambios de tangentes.
- Modificación de parámetros.
- Transformaciones.
- Cambios de simetría.
- Modificación de la celda.
- Ajustes de distribución.

### 7.2 Área de visualización

El patrón puede extenderse virtualmente más allá del viewport.

Calcular y dibujar solamente las instancias relevantes para la región visible, con margen suficiente para evitar aparición tardía de elementos durante el pan.

No generar una cantidad infinita de objetos.

### 7.3 Guías

Permitir mostrar u ocultar:

- Celda fundamental.
- Celda de repetición.
- Vectores de red.
- Ejes de simetría.
- Centros de rotación.
- Centros de reflexión.
- Límites del área visible.
- Grilla de coordenadas.

Las guías no forman parte de la exportación, salvo pedido explícito.

### 7.4 Vista de continuidad

Incluir un modo de inspección de bordes.

Para patrones periódicos:

- Mostrar varias celdas adyacentes.
- Resaltar fronteras de la celda.
- Detectar errores geométricos o discontinuidades no esperadas.
- Permitir comprobar el comportamiento bajo ambas traslaciones de la red.

La continuidad debe resultar de las transformaciones matemáticas, no de disimular costuras mediante rasterizado.

## 8. Aplicación del patrón a un perímetro irregular

### 8.1 Objetivo

Cualquier patrón disponible debe poder aplicarse a una región plana definida por un path vectorial cerrado.

No incluir plantillas especializadas en objetos, industrias o productos físicos.

### 8.2 Creación de perímetros

El usuario podrá:

- Dibujar un perímetro con pluma Bézier.
- Dibujar un polígono irregular.
- Importar un SVG con una o varias regiones cerradas.
- Editar nodos del perímetro.
- Modificar dimensiones.
- Trasladar, rotar y escalar.
- Crear regiones con agujeros internos mediante paths compuestos.

Validar que la geometría pueda interpretarse como región cerrada.

No cerrar silenciosamente paths abiertos importados.

### 8.3 Aplicación del patrón

Al elegir un perímetro:

1. Seleccionar un patrón existente.
2. Mostrarlo inmediatamente dentro de la región.
3. Mantener el patrón original independiente.
4. Permitir desplazar, rotar y escalar el patrón.
5. Modificar su fase respecto del origen.
6. Ajustar parámetros del patrón sin cambiar el perímetro.
7. Editar el perímetro sin regenerar destructivamente el patrón.
8. Permitir cambiar el patrón por otro.
9. Mantener la vinculación entre fuente y aplicación.

### 8.4 Controles

- Escala X/Y.
- Escala uniforme.
- Rotación.
- Traslación.
- Origen/anclaje.
- Fase.
- Densidad, cuando corresponda.
- Mostrar contorno.
- Mostrar patrón fuera del contorno en modo de edición.
- Ocultar geometría externa en previsualización.

No calcular automáticamente una deformación para que el patrón siga los bordes del perímetro.

**La operación inicial es un relleno geométrico 2D recortado.**

No es un mapeo no lineal ni un ajuste de textura por curvatura.

### 8.5 Recorte

Soportar dos modalidades:

**Visual no destructiva**

El perímetro actúa como máscara y la geometría fuente permanece intacta.

**Geometría expandida**

Generar trazados reales limitados por el perímetro.

Para trazos abiertos, aplicar un algoritmo de recorte de curvas o segmentos adecuado. Para regiones rellenas, aplicar operaciones geométricas robustas.

Cuando el usuario solicite contornos cerrados, convertir primero los trazos en regiones con ancho y después efectuar las operaciones booleanas necesarias.

El resultado expandido debe ser independiente del motor del programa.

### 8.6 Múltiples aplicaciones

Un proyecto puede contener:

- Varios patrones.
- Varios perímetros.
- Varias aplicaciones de un mismo patrón.
- Parámetros de colocación independientes por aplicación.

Modificar el patrón fuente debe actualizar sus aplicaciones vinculadas.

No alterar las aplicaciones desvinculadas o expresamente congeladas.

## 9. Medidas y precisión

### 9.1 Sistema de coordenadas

Utilizar unidades de documento independientes del zoom y de la resolución física de pantalla.

Definir claramente la transformación entre:

- Coordenadas del modelo.
- Coordenadas de pantalla.
- Coordenadas de archivo exportado.

Unidad interna canónica recomendada: milímetros para documentos con dimensiones físicas.

### 9.2 Unidades

Soportar:

- mm
- cm
- pulgadas
- px

Mostrar conversiones coherentes.

Un cambio de unidad de presentación no debe modificar las dimensiones físicas.

### 9.3 SVG importado

Interpretar correctamente `viewBox`, unidades explícitas y transformaciones.

Si un SVG no expresa dimensiones físicas inequívocas, permitir definirlas sin inventar una escala silenciosamente.

### 9.4 Precisión

- Coordenadas de doble precisión durante el cálculo.
- Tolerancias geométricas centralizadas y documentadas.
- Evitar redondeos acumulativos durante la edición.
- No utilizar píxeles de pantalla como precisión geométrica.
- Un ciclo guardar/abrir no debe modificar dimensiones ni nodos más allá de la tolerancia serializada.

MUST soportar:

- SVG.
- JSON nativo de proyecto.

Para SVG:

- Shapes y paths vectoriales.
- Paths compuestos.
- Transformaciones.
- Grupos compatibles.
- Dimensiones y `viewBox`.

No prometer soporte universal de todas las características SVG. Detectar explícitamente filtros, imágenes incrustadas, texto u otras capacidades no soportadas y advertir cuando sea necesario.

### 10.2 SVG — Patrón periódico

Exportar:

- Celda fundamental cuando corresponda.
- Celda de repetición.
- Patrón SVG mediante definiciones reutilizables cuando sea compatible.
- Patrón expandido en una región finita configurable.

La información geométrica del patrón debe conservarse.

### 10.3 SVG — Patrón aplicado

Exportar:

- Previsualización con clipPath.
- Geometría expandida y recortada.
- Contorno de aplicación opcional.
- Todo en dimensiones físicas correctas.

Una exportación llamada **Expanded SVG** no puede depender de una máscara visual para ocultar geometría que supuestamente ya está recortada.

### 10.4 Otros formatos

**PNG**

- Fondo transparente o sólido.
- Resolución configurable.
- DPI configurable.
- Respeto de dimensiones físicas.
- Exportación de celda o región aplicada.

**JPEG**

- Calidad configurable.
- Fondo sólido.
- Destinado a representación rasterizada, nunca como formato principal editable.

**DXF**

- Exportación 2D básica de líneas y polilíneas.
- Curvas Bézier aproximadas mediante subdivisión controlada.
- Tolerancia de aproximación configurable en unidades físicas.
- No incluir entidades 3D.
- Documentar limitaciones y preservar la escala.

**JSON**

- Proyecto editable y recuperable.
- Versión de esquema explícita.
- Todos los parámetros, vínculos y objetos fuente.

### 10.5 Seguridad y validez

Los SVG importados deben procesarse como contenido no confiable.

Rechazar o sanitizar scripts, manejadores de eventos, contenido activo, referencias remotas peligrosas y elementos no permitidos.

No ejecutar JavaScript importado.

Los SVG exportados deben ser XML válido, autocontenido y visualizable sin depender de recursos externos.

### 10.6 Previsualización de exportación

El diálogo Exportar MUST permitir:

- Elegir qué exportar.
- Elegir formato.
- Configurar dimensiones o resolución.
- Seleccionar representación editable o expandida.
- Ver una previsualización.
- Informar el tamaño estimado de la exportación.
- Advertir si el resultado no cumple las condiciones para exportación seamless rectangular.

Las exportaciones costosas deben permitir cancelación.

## 13. Performance

### 13.1 Objetivo interactivo

La experiencia debe mantenerse fluida durante:

- Dibujo libre.
- Manipulación Bézier.
- Drag de objetos.
- Cambios de sliders.
- Zoom.
- Pan.
- Cambio de simetría.

Objetivo de referencia:

- Al menos 30 FPS durante interacciones habituales sobre un equipo desktop moderno.
- Latencia visible de actualización idealmente inferior a 100 ms para escenas normales.
- Sin bloqueo prolongado del hilo principal por exportaciones.

Estos son objetivos medibles, no garantías para geometrías arbitrariamente grandes.

### 13.2 Escena de prueba

Preparar un benchmark con:

- 100 objetos fuente.
- 300 instancias de celda visibles.
- Al menos un grupo con reflexiones y rotaciones.
- Un generador con parámetros variables.
- Un perímetro irregular.

Medir la respuesta al arrastrar un nodo y cambiar un parámetro.

### 13.3 Estrategias

- Renderizar solo el área visible.
- Cachear geometrías y transformaciones cuando corresponda.
- Evitar duplicación innecesaria de paths.
- Invalidar solamente las etapas afectadas.
- Debounce para operaciones realmente costosas, sin comprometer la respuesta del trazo.
- Web Worker para expansiones y exportaciones pesadas.
- Límites configurables de complejidad y consumo de memoria.
- Indicadores de procesamiento y cancelación.

El resultado exportado debe obtenerse del modelo geométrico, no de una captura de baja resolución del viewport.

## 14. Pruebas y criterios de aceptación

Crear pruebas unitarias, geométricas, funcionales y end-to-end.

### AC-01 — Primera línea

Con un proyecto vacío en modo periódico, empezar a dibujar una línea.

**Esperado:** antes de soltar el mouse, sus copias aparecen en la vista del patrón.

### AC-02 — Modificación de geometría

Mover un nodo Bézier del motivo original.

**Esperado:** todas las instancias se actualizan y la curva permanece editable.

### AC-03 — Edición mediante instancia

Seleccionar una copia reflejada o rotada y mover un nodo.

**Esperado:** se modifica el nodo correspondiente de la geometría fuente y todas las copias permanecen consistentes.

### AC-04 — Simetrías periódicas

Probar los 17 wallpaper groups con motivos asimétricos.

**Esperado:** las transformaciones cumplen las simetrías definidas y son invariantes bajo los vectores de la red.

Incluir casos específicos para p4m, p4g, p6m, pg y pgg.

### AC-05 — Frisos y rosetas

Cambiar parámetros de repetición lineal y radial.

**Esperado:** las instancias respetan las transformaciones correspondientes sin introducir traslaciones periódicas inexistentes.

### AC-06 — Seamless

Construir una geometría que atraviese el borde de la celda.

**Esperado:** la unión con las celdas vecinas es geométricamente continua.

Automatizar pruebas con traslaciones y, para exportaciones rasterizables periódicas rectangulares, comparación de mosaicos de varias celdas.

### AC-07 — Deformación

Aplicar un warp periódico compatible.

**Esperado:** conserva continuidad por traslación.

Aplicar uno incompatible con la simetría estricta elegida.

**Esperado:** la aplicación restringe el warp o advierte claramente la pérdida de simetría.

### AC-08 — Generador paramétrico

Crear un Warp Grid, modificar grid size, spacing, scale ratio y modo de distribución.

**Esperado:** actualización inmediata, determinística y recuperable mediante undo.

### AC-09 — Aplicación a perímetro

Importar o crear una región Bézier irregular.

Aplicarle un patrón, moverlo, rotarlo y escalarlo.

**Esperado:** solo aparece dentro de la región en el modo de previsualización recortada; la fuente sigue intacta.

### AC-10 — Paths compuestos

Crear una región externa con agujero interior.

**Esperado:** el patrón no invade el agujero y la exportación expandida respeta ambas fronteras.

### AC-11 — Exportación expandida

Exportar el resultado aplicado a una región irregular.

**Esperado:** el SVG expandido contiene geometría efectivamente recortada y no necesita un clipPath para producir ese recorte.

### AC-12 — Medidas

Crear un rectángulo de 100 × 50 mm, guardar, reabrir y exportar.

**Esperado:** dimensiones físicas conservadas dentro de una tolerancia documentada.

### AC-13 — Proyecto completo

Guardar un proyecto con varias geometrías, simetrías, generadores, regiones y aplicaciones.

Abrirlo nuevamente.

**Esperado:** resultado y parámetros idénticos.

### AC-14 — Determinismo

Generar dos veces el mismo patrón con parámetros, semilla y versiones de algoritmo idénticos.

**Esperado:** geometría equivalente dentro de la tolerancia matemática definida.

### AC-15 — Exportación

Abrir los SVG producidos en un renderizador externo y comprobar que mantienen geometría, dimensiones y apariencia.

Comprobar también PNG y DXF con herramientas o validadores independientes.

### AC-16 — SVG malicioso

Importar SVG con scripts, atributos de evento y recursos externos.

**Esperado:** ningún código se ejecuta y los elementos peligrosos son rechazados o sanitizados.

### AC-17 — Despliegue estático

Ejecutar el build de producción desde:

1. Raíz de un servidor estático.
2. Subdirectorio configurado.
3. Servidor HTTP local accesible desde otra máquina.

**Esperado:** todas las funciones operan sin backend y sin conexión a servicios externos.

### AC-18 — Regresión visual

Crear capturas automatizadas de los modos EDIT, PATTERN y APPLY con un proyecto de prueba.

Verificar posición de paneles, visualización de controles y ausencia de superposiciones a resoluciones desktop.

### AC-19 — Historial

Dibujar, modificar y transformar una geometría, cambiar su simetría y aplicar un patrón.

Ejecutar undo y redo.

**Esperado:** recuperación correcta de cada estado, sin inconsistencias entre datos y pantalla.

### AC-20 — Funcionalidad real

Inspeccionar todos los controles visibles del editor.

**Esperado:** ninguna herramienta presentada como funcional carece de comportamiento implementado.

# Resultado esperado

Una herramienta de diseño vectorial 2D en la que el usuario pueda comenzar con una sola línea, observar inmediatamente su transformación en un patrón complejo, modificar libremente la geometría y sus parámetros, cambiar entre diferentes sistemas de simetría, aplicar el resultado a cualquier perímetro irregular y exportarlo sin perder precisión.

La aplicación debe combinar la inmediatez y simplicidad visual de Patturn Studio con la flexibilidad de un editor vectorial no destructivo y un motor geométrico matemáticamente riguroso.

**Este PRD es la especificación de implementación. Procedé con el desarrollo completo.**
